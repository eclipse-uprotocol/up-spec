== Overview

https://cloudevents.io/[CloudEvents] is a specification hosted by the https://cncf.io/[Cloud Native Computing Foundation] (CNCF) for describing events in a common way.

The CloudEvents specification defines an envelope for carrying information about the occurrence of a noteworthy event in a system.

.CloudEvents envelope
image::cloudevents.drawio.svg[CloudEvents]

CloudEvents

* are self-contained & unique,
* contain standardized metadata in the header,
* contain optional context information in its data section,
* can be represented using different formats without losing/modifying information.

The metadata contained in an event covers questions like

* What kind of event has occurred?
* When did it occur?
* Where did it occur?
* What context did the event occur in?

Support for using CloudEvents is available for many programming languages by means of corresponding SDKs.

The https://cloudevents.io/[CloudEvents] project has defined a set of *Formats* which describe how events can be expressed using https://github.com/cloudevents/spec/blob/v1.0.2/cloudevents/formats/json-format.md[JSON], https://github.com/cloudevents/spec/blob/v1.0.2/cloudevents/formats/protobuf-format.md[Protobuf] or https://github.com/cloudevents/spec/blob/v1.0.2/cloudevents/formats/avro-format.md[Apache Avro].

The accompanying *Bindings* describe how events can be sent via well-known transport protocols like https://github.com/cloudevents/spec/blob/v1.0.2/cloudevents/bindings/http-protocol-binding.md[HTTP], https://github.com/cloudevents/spec/blob/v1.0.2/cloudevents/bindings/mqtt-protocol-binding.md[MQTT] etc.

=== uPayload Mapping

The sections below define the mapping of uPayload to CloudEvent attributes.
The opaque-carriage mapping preserves a UMessage payload's serialized octets,
encoding identifier, and presence without requiring the binding to interpret
the payload. The xref:#ce-legacy-input[legacy typed-input rules] describe the
limited reconstruction of older representations; JSON-value reconstruction
preserves the value but cannot recover its original byte spelling.
Application-aware operations that interpret a payload, such as projecting it
into an event format's native data model, are outside this mapping; see
xref:#ce-projection-note[Application-Aware Projection].

[#ce-opaque-carriage]
==== Opaque Carriage

A CloudEvent carries the original payload bytes and the original identifier in
`pformat`. When sending an opaque payload, `datacontenttype` is
`application/octet-stream`: it describes the carriage form, while `pformat`
identifies the encoding. The carriage form does not change with the encoding.

The following tables preserve payload presence, bytes, and identity without
requiring the binding to read the payload.

[.specitem,oft-sid="dsn~ce-payload-opaque-carriage~1",oft-needs="impl,utest",oft-tags="TransportLayerImpl"]
--
.UMessage to CloudEvent
[cols="2,5", options="header"]
|===
|Condition |Required result

|`payload` absent
|The CloudEvent *MUST NOT* contain a payload data property, `pformat`, or
payload-specific `datacontenttype` or `dataschema` values.

|`payload` present, including zero bytes
|The CloudEvent *MUST* carry those octets unchanged in `binary_data` (Protobuf
Event Format) or `data_base64` (JSON Event Format), keep the identifier unchanged
in `pformat`, and set `datacontenttype` to `application/octet-stream`.
|===

For a present payload, `dataschema` *MAY* name its schema with a non-empty
absolute URI as defined by CloudEvents. It *MUST NOT* determine the encoding;
carriage requires no schema lookup.

The binding *MUST NOT* change `pformat`, relabel the payload, wrap or unwrap
Protobuf `Any` messages, convert character encodings, or inspect the payload
bytes to choose a data property.

.CloudEvent to UMessage
[cols="2,5", options="header"]
|===
|Condition |Required result

|No payload data property
|Both `payload` and `payload_encoding_id` *MUST* be absent.

|Binary payload (`binary_data` or `data_base64`)
|`payload` *MUST* contain exactly those octets and `payload_encoding_id` *MUST*
equal `pformat`, even when `datacontenttype` is absent or is not
`application/octet-stream`.

|Typed payload data property
|The binding *MUST* apply xref:#ce-legacy-input[Legacy Typed Input].
|===

`datacontenttype` *MUST NOT* determine or override `payload_encoding_id`.
Recognizing the identifier *MUST NOT* cause the binding to decode the payload.
--

An encoding's registered media type describes its application representation;
it is not the media type used to carry its opaque bytes in this mapping.

This preservation guarantee applies to the defined UMessage data and attributes,
not to every additional CloudEvents attribute. In particular, UMessage has no
general field for retaining an arbitrary `dataschema` URI. Where schema context
is needed after conversion, the applicable service or representation contract
must provide it; this mapping does not require network schema resolution.

[#ce-legacy-input]
==== Legacy Typed Input

Earlier versions put some payloads in typed fields. Receivers *MUST* keep
accepting the exact forms below; no other typed input is accepted by this mapping.

Guarantees differ by form. Opaque carriage preserves the payload's octets
exactly. The Protobuf Event Format legacy forms preserve octets exactly. The
JSON Event Format legacy form for identifier `3` preserves the JSON value but
cannot recover the original byte spelling of the JSON text.

[.specitem,oft-sid="dsn~ce-payload-legacy-input~1",oft-needs="impl,utest",oft-tags="TransportLayerImpl"]
--
When mapping a CloudEvent that contains a typed payload data property to a
UMessage, the binding *MUST* reconstruct the payload as follows, and *MUST*
reject any other combination of `pformat`, event format, and typed payload
data property:

.Legacy Protobuf Event Format
[cols="2,5", options="header"]
|===
|Form |What is preserved

|`pformat` `1` or `2` with `proto_data`
|The `value` octets of the `proto_data` `Any` message, unchanged. Its `type_url`
*MAY* be empty and *MUST NOT* be used to reconstruct or validate the payload. For `pformat`
`1`, those octets are already the serialized payload `google.protobuf.Any`;
the binding *MUST NOT* serialize the outer `proto_data` message.

|`pformat` `3` or `7` with `text_data`
|The UTF-8 bytes of the `text_data` string.
|===

.Legacy JSON Event Format (`data` member present)
[cols="2,5", options="header"]
|===
|Form |What is preserved

|`pformat` `3`; `datacontenttype` absent or declaring JSON-formatted content
|The JSON value, serialized as UTF-8 JSON. A string becomes a quoted JSON string;
`null` becomes the four octets `null` as a present payload. The `data` member
*MUST NOT* be further parsed as a JSON document. Its original byte spelling
cannot be recovered.

|`pformat` `7`; `data` is a JSON string
|The UTF-8 bytes of the string's characters.
|===
--

These rules cover the forms defined by earlier revisions of this binding and
the historical uProtocol Rust profile, whose Protobuf Event Format writer stores
the payload octets in `proto_data.value` with an empty `type_url` for both
identifiers `1` and `2`. An implementation that used a different convention,
such as placing the payload `Any` directly in `proto_data` or placing a
serialized JSON document inside a JSON string, is not covered by these rules.
Such a convention requires its own evidenced compatibility contract and an
explicit selection mechanism; the binding *MUST NOT* infer which convention
applies by inspecting payload bytes.

[#ce-projection-note]
==== Application-Aware Projection

NOTE: A component that owns a payload's contract may choose to represent that
payload in an event format's native data model, for example as a JSON value or
as a typed `proto_data` message, for consumers outside uProtocol. Such a
projection interprets the payload and is an application-level operation
performed at an endpoint, not part of this binding's carriage mapping. It is
never selected by recognizing an identifier, it does not change how the binding
carries the message, and this specification does not define its selection,
its output, or any receiver support for it. Deployments that need readable
JSON event data would do so through such an operation.

==== Mapping to CloudEvent Protobuf Format

The rules defined in https://github.com/cloudevents/spec/blob/v1.0.2/cloudevents/formats/protobuf-format.md[Protobuf Event Format for CloudEvents, Version 1.0.2] MUST be applied when mapping UPayload to CloudEvents using the Protobuf Format.

This mapping *MUST* be used by uProtocol Transport Libraries which use the Protobuf Event Format for the binding to a particular transport protocol.

[%autowidth]
|===
|UMessage payload |CE `pformat` |CE `datacontenttype` |CE `dataschema` |CE payload data property

|absent
|absent
|absent
|absent
|none

|present, any identifier `0` to `65535`, including zero-length
|the identifier, unchanged
|`application/octet-stream`
|*MAY* be set to a non-empty absolute URI identifying the schema
|`binary_data` holding the payload octets unchanged (empty for a zero-length payload)
|===

==== Mapping to CloudEvent JSON Format

The rules defined in https://github.com/cloudevents/spec/blob/v1.0.2/cloudevents/formats/json-format.md[JSON Event Format for CloudEvents, Version 1.0.2] MUST be applied when mapping UPayload to CloudEvents using the JSON Format.

This mapping *MUST* be used by uProtocol Transport Libraries which use the JSON Event Format for the binding to a particular transport protocol.

[%autowidth]
|===
|UMessage payload |CE `pformat` |CE `datacontenttype` |CE `dataschema` |CE payload data property

|absent
|absent
|absent
|absent
|none

|present, any identifier `0` to `65535`, including zero-length
|the identifier, unchanged
|`application/octet-stream`
|*MAY* be set to a non-empty absolute URI identifying the schema
|`data_base64` holding the Base64 encoding of the payload octets (an empty string for a zero-length payload)
|===

The JSON Event Format carries every payload, including JSON and UTF-8 text
payloads, as `data_base64`. This preserves the exact octets at the cost of
Base64 expansion and readability.

==== Additional Recommendations

CloudEvents *SHOULD* only be serialized when they are about to be sent via the xref:README.adoc#_utransport[UTransport interface]

== Examples

The following examples use the CloudEvent JSON Format with the opaque carriage
baseline. The notification's `data_base64` value decodes to the JSON text
`{"subject":"door.front_left","status":"open"}`; the publish example's decodes
to the UTF-8 text `open`.

=== Publish
[source, json]
----
{
    "specversion": "1.0",
    "id": "cf8b1bcd-30bd-43be-a8d3-ad1cde652e10",
    "source": "//VCU.VIN/body.access/1/door.front_left#Door",
    "type": "up-pub.v1",
    "priority": "CS1",
    "ttl": 10000,
    "pformat": 7,
    "datacontenttype": "application/octet-stream",
    "data_base64": "b3Blbg=="
}
----
